# Changesets

This folder holds the pending release notes and, while the next line is a prerelease, `pre.json`. The
versioner is dependency-free (`scripts/release/`, B15 [#190](https://github.com/Laratypes/Laratype/issues/190));
the file format is the changesets one so a later migration stays mechanical.

## Add a note

Every PR that changes a published package adds one file, either with the command or by hand:

```sh
bun run release:changeset @laratype/http minor "Describe the change"
```

```md
---
"@laratype/http": minor
---

Describe the change.
```

- The package must be one of the public packages under `packages/*`; a private package is rejected.
- The bump is `patch`, `minor` or `major`. The repo uses **fixed versioning**: every public package gets the same
  version, and the highest pending bump decides it outside pre mode. A `major` bump on `0.x` is `1.0.0`.
- The summary is the changelog entry: it cannot be empty, is limited to 2000 characters, and must not contain
  control characters or unpaired UTF-16 surrogates. LF and TAB are fine. CRLF files are accepted and normalized.
- The file name is generated by `release:changeset` (package, bump and a random suffix); never pass a path.

## Version and publish

`bun run release:version` writes the next fixed version into every `packages/*/package.json` and the root, prepends
the version to `CHANGELOG.md`, and deletes the applied `.md` files. See
[docs/v1/build.md › CI and release](../../docs/v1/build.md#ci-and-release) for the full release procedure.

## Pre mode

`.changeset/pre.json` holds `{"mode":"pre","tag":"alpha","base":"<next stable line>"}`. While it exists,
`release:version` writes `<base>-alpha.<N>` and a bump never moves the line; `bun run release:pre-exit` removes it and
the next `release:version` writes `<base>`. Pending changesets at that point only contribute their notes to the stable
section, never a bump. Only `alpha` is a configured prerelease dist-tag; a stable version publishes to `latest`.
